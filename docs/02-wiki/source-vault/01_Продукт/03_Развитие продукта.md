## Ближайший план

### Этап 1. Публикация Wiki

Опубликовать описание продукта, процесса, архитектуры, данных и проверок на GitHub Pages. Результат этапа — работоспособный сайт документации, который можно изучить без установки Obsidian.

### Этап 2. Первый функциональный прототип

Разработать Telegram-бота для создания заявки, проверки обязательных данных, выдачи номера и просмотра/изменения статуса уполномоченным пользователем. Результат этапа — основной сценарий обработки заказа проходит без разрозненной переписки.

### Этап 3. Расширение исполнения и документов

Добавить мобильный сценарий водителя: отметка подачи, фото груза, статус доставки и загрузка накладной. Результат этапа — документы и фактические события доступны прямо в карточке.

### Этап 4. Аналитика и дополнительные интерфейсы

Добавить просмотр статуса, скачивание документов, историю уведомлений и дашборд KPI. Результат этапа — клиент получает самообслуживание, а руководитель видит качество процесса.

## План проверки с пользователями

На учебном тестировании каждому пользователю выдаётся сценарий: менеджеру — принять неполную заявку, диспетчеру — обработать риск опоздания, водителю — загрузить фото и ТТН, бухгалтеру — закрыть заказ, клиенту — проверить статус. Для каждого сценария фиксируются время выполнения, непонятные поля и ошибки навигации.
