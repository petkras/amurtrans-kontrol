# Программные и аппаратные требования

## Назначение

Wiki продукта публикуется как статический сайт GitHub Pages. Она открывается в браузере, сохраняет читаемость на компьютере и телефоне и обеспечивает рабочие ссылки, поиск по страницам, доступные таблицы и изображения схем.

Целевая система обработки заказов включает Telegram-интерфейс и постоянное хранилище. Требования ниже описывают поведение такой системы.

## Требования к сайту Wiki

| Область | Требование | Проверка |
|---|---|---|
| Доступность | опубликованные страницы доступны без входа в Obsidian | открыть прямые ссылки на страницы в браузере |
| Навигация | любой основной раздел доступен из меню; есть переходы между связанными статьями | пройти основные пользовательские маршруты |
| Поиск | запрос находит страницы по названию и содержанию | выполнить поиск по нескольким терминам |
| Адаптивность | текст и схемы читаемы на узком экране без наложения элементов | проверить ширины телефона и рабочего стола |
| Публикация | сайт состоит из статических HTML, CSS, JavaScript и изображений | проверить структуру сборки и работу ссылок |

## Требования к будущему Telegram-боту

| Область | Требование | Причина |
|---|---|---|
| Доступ | сотрудник может менять только разрешённые ему статусы | защита данных и порядка процесса |
| Заявка | обязательные поля проверяются до присвоения номера | снижение числа уточнений |
| История | изменение этапа сохраняет время, автора и комментарий | разбор задержек и спорных ситуаций |
| Данные | сведения о заказах хранятся вне временной среды выполнения бота | сохранность между обращениями |
| Секреты | токен бота хранится вне репозитория | предотвращение несанкционированного доступа |
| Языковая модель | модель может извлекать поля из свободного текста, но ответ проверяется серверной схемой | контроль ошибок и запрет прямого изменения заказа моделью |
| Доступность диалога | заявка оформляется пошагово и без LLM | сохранение основного сценария при недоступности модели |

## Рабочее место пользователя

Для Wiki нужен современный браузер. Для будущего бота — приложение Telegram и доступ в интернет. Отдельный установочный файл или `.exe` для чтения Wiki не требуется.

## Выбор серверной инфраструктуры

Серверная функция бота размещается на Vercel и принимает Telegram HTTPS webhook. Для разбора свободного текста выбран кандидат `meta/llama-4-scout`, вызываемый через Vercel AI Gateway; inference выполняется API-провайдером, модель не загружается в среду Vercel Function. Постоянная база данных хранит заказы и их историю. Стоимость и точность модели проверяются по тестовым сообщениям; при ошибке или тайм-ауте используется пошаговый сценарий.

Внешние почтовые, SMS, GPS, картографические и файловые сервисы не требуются основному сценарию.

## Технические источники

- [Карточка `Llama 4 Scout` в Vercel AI Gateway](https://vercel.com/ai-gateway/models/llama-4-scout) — идентификатор модели, провайдеры и опубликованные тарифы.
- [Vercel Functions](https://vercel.com/docs/functions) — серверные функции для обработки HTTP-запросов и вызова API.
- [Telegram Bot API: `setWebhook`](https://core.telegram.org/bots/api#setwebhook) — HTTPS POST, повторная доставка и секретный заголовок webhook.
