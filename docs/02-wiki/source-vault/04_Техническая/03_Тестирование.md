# Тестирование

## Цель

Тестирование подтверждает, что заказ проходит все обязательные этапы, статусы не противоречат друг другу, а документы и уведомления доступны нужным ролям.

## Набор проверок MVP

| Уровень | Объект проверки | Пример ожидаемого результата |
| --- | --- | --- |
| Модульный | расчёт тарифа и проверка обязательных полей | нельзя сохранить заказ без маршрута и контакта |
| Интеграционный | создание рейса по заказу | статус заказа меняется на «Назначен транспорт» |
| Сквозной | путь от заявки до акта | история содержит все контрольные события |
| Приёмочный | работа менеджера и диспетчера | пользователь выполняет сценарий без обхода регламента |
| Нагрузочный | список активных рейсов | панель открывается при 100 одновременных пользователях |

## Критерии готовности релиза

- не остаётся критических ошибок по основному сценарию заказа;
- статусы заказа и рейса согласованы;
- доступы проверены для всех ролей;
- резервная копия восстанавливается на тестовом контуре;
- владелец процесса принимает сквозной сценарий.

Результаты проверок фиксируются в карточке задачи технической очереди. Ошибка, влияющая на расчёт, документы или доступ к персональным данным, имеет высокий приоритет.
